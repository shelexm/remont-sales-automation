# Воспроизводимый локальный стенд

Этот стенд запускает отдельные контейнеры PostgreSQL, приёмника, n8n и EspoCRM на компьютере. Он предназначен **только для вымышленных данных**: это не production-конфигурация. Tilda, HTTPS-туннель, Telegram, мониторинг и резервные копии автоматически не настраиваются. При выключении компьютера обработка останавливается. Существующие контейнеры n8n, базы и CRM не изменяются, если имена проектов и томов не совпадают.

## Подготовка

Из корня репозитория создайте `.env` из `.env.example` и замените `POSTGRES_PASSWORD` и `WEBHOOK_KEY` на случайные буквенно-цифровые значения длиной не менее 32 символов. В `infra/local-demo/.local/demo.env` скопируйте `infra/local-demo/env.example`: задайте три разные надёжные пароли CRM и случайный `N8N_ENCRYPTION_KEY` длиной не менее 32 буквенно-цифровых символов. После настройки EspoCRM укажите в этом файле `LOCAL_ESPO_API_KEY` и `LOCAL_ESPO_OWNER` для отдельного API-пользователя. Не используйте примеры вместо секретов и не размещайте файл в Git.

Создайте локальный центр сертификации и сертификат прокси:

```sh
python3 infra/local-demo/prepare_tls.py
```

Скрипт не перезаписывает существующие ключи. При частично созданных файлах он останавливается: перед ротацией сохраните резервную копию и проверьте, какой стенд использует эти ключи. Сертификат CRM действует 90 дней, локальный CA — год. Каталог `.local/` содержит секреты, исключён из Git и должен быть доступен только владельцу.

## Запуск

Команды ниже выполняются из корня репозитория. Они используют отдельные имена проектов `remont-local-crm`, `remont-trial` и `remont-local-automation`; заранее проверьте, что они не заняты другими сервисами. Не выполняйте `down --volumes` для хранилищ, которые нужно сохранить.

1. Запустите локальную CRM и базовый стенд:

   ```sh
   docker compose --env-file infra/local-demo/.local/demo.env -f infra/local-demo/crm-compose.yaml up -d
   docker compose -p remont-trial --env-file .env up -d --build db migrate receiver
   ```

2. Настройте локальную EspoCRM по [инструкции интеграции](../../docs/integrations.md): API-пользователя с ограниченной ролью, поля `cAutomationKey`, рубли и стадию сделки. Внесите ключ API и ID пользователя в `infra/local-demo/.local/demo.env`. CRM доступна только на `http://127.0.0.1:18090`.

3. Запустите внутренний TLS-прокси и инициализируйте отдельный n8n:

   ```sh
   docker compose --env-file infra/local-demo/.local/demo.env -f infra/local-demo/compose.yaml up -d crm-proxy
   python3 infra/local-demo/bootstrap_n8n.py
   docker compose --env-file infra/local-demo/.local/demo.env -f infra/local-demo/compose.yaml up -d n8n
   ```

   Инициализация импортирует credential и workflow через стандартный ввод, публикует workflow и отказывается работать, если том n8n уже существует. Секреты не записываются во временные файлы и журналы. Если инициализация прервалась, новый том сохраняется для проверки; скрипт не удаляет и не перезаписывает его. `--project-name` задаёт другое имя изолированного проекта, если это необходимо.

4. Запустите обработчик сразу с локальной EspoCRM (не запускайте перед этим demo-обработчик на той же базе: первая CRM привязывается к базе):

   ```sh
   docker compose -p remont-trial --env-file .env --env-file infra/local-demo/.local/demo.env -f compose.yaml -f infra/local-demo/integrations-override.yaml up -d --no-deps integrations
   ```

   При дальнейших запусках обработчика используйте оба Compose-файла: без override стандартный конфиг вернётся к `CRM_PROVIDER=demo`. TLS проверяется на участке от обработчика до прокси; от прокси до CRM используется HTTP в Docker-сети. Доверие к публичным CA сохранено для будущего Telegram. Локальный n8n подключается к PostgreSQL по внутренней сети с пользователем проекта; ограничение прав БД для production ещё не выполнено.

5. Проверьте `docker compose ... ps`, отправьте вымышленную заявку в приёмник и убедитесь в завершении задания CRM и появлении контакта и сделки. `GET /health` проверяет только процесс приёмника. Инструкции по форме, Telegram и диагностике — в [приёме заявок](../../docs/lead-intake.md) и [интеграциях](../../docs/integrations.md).

## Подключение Telegram для теста

Создайте отдельного бота в BotFather. Сохраните его токен в файл `infra/local-demo/.local/telegram-token` с правами `600`, не размещая токен в Git, командной строке или переписке. Например, из корня репозитория можно безопасно ввести его без отображения на экране:

```sh
python3 -c 'import getpass, os; p="infra/local-demo/.local/telegram-token"; fd=os.open(p,os.O_WRONLY|os.O_CREAT|os.O_EXCL,0o600); os.write(fd,(getpass.getpass("Токен бота: ")+"\n").encode()); os.close(fd)'
```

Скрипт не перезапишет существующий файл. Затем выполните `python3 infra/local-demo/telegram_setup.py challenge` и отправьте выданный одноразовый код в личном чате указанного бота после нажатия «Запустить». На некоторых установках Python для macOS необходимо задать системные корневые сертификаты: `SSL_CERT_FILE=/etc/ssl/cert.pem python3 infra/local-demo/telegram_setup.py challenge`. Код используется только для привязки чата и не заменяет токен.

После отправки кода выполните `python3 infra/local-demo/telegram_setup.py bind` (при необходимости с тем же `SSL_CERT_FILE`). Скрипт выберет ровно один личный чат с совпадающим кодом, сохранит токен и ID чата в `.local/telegram.env` с правами `600` и удалит одноразовый код. При неоднозначности или существующем файле настройки он остановится, ничего не перезаписывая. До включения просмотрите очередь: старые ожидающие задания могут породить уведомления и напоминания.

Включите Telegram, добавив третий env-файл и override:

```sh
docker compose -p remont-trial --env-file .env --env-file infra/local-demo/.local/demo.env --env-file infra/local-demo/.local/telegram.env -f compose.yaml -f infra/local-demo/integrations-override.yaml -f infra/local-demo/telegram-override.yaml up -d --no-deps integrations
```

Далее при перезапуске обработчика используйте все три env-файла и оба override. При смене или компрометации токена перевыпустите его в BotFather, обновите защищённые локальные файлы и пересоздайте обработчик; старый токен больше не используйте. Не повторяйте автоматически задания `uncertain`: их доставка могла состояться, поэтому сначала сверьте чат.

Для постоянного использования нужны стабильный защищённый адрес, документы оператора, отдельные права, мониторинг, резервные копии и проверка их восстановления. Временные Quick Tunnel не дают стабильного адреса и могут перестать работать после перезапуска.
