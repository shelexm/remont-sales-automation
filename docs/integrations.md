# Интеграции: предварительная версия

После внутренней обработки события триггер добавляет отдельные задания CRM и Telegram. Обработчик `integrations` читает задания из PostgreSQL. Каждая доставка имеет статус, счётчик попыток, задержку и ограниченную аренду. Сообщения не содержат имени или телефона; технические ошибки хранятся как короткие коды.

## CRM

`CRM_PROVIDER=demo` — тестовый провайдер, сохраняет синтетическую CRM в таблице `demo_crm` и не связывается с внешней системой. Уникальная карточка задаётся `case_id`; повторная обработка обновляет её. Это не настоящая CRM. `CRM_PROVIDER=espocrm` — предварительный адаптер REST API с параметрами `ESPO_URL` (HTTPS) и `ESPO_API_KEY`. В EspoCRM нужно создать отдельного API-пользователя с минимальными правами на Contact и Opportunity и текстовое поле `cAutomationKey` в каждой сущности. Проверьте имена полей, доступ на поиск и связь контакта со сделкой на тестовом экземпляре. Никакой реальной EspoCRM в этом проекте ещё не настроено и работоспособность адаптера с ней не подтверждена.

При создании сущности адаптер записывает намерение в `crm_entities`, затем делает POST. При повторной обработке он сначала ищет технический ключ в CRM. Если результат предыдущего создания неизвестен и поиск ничего не нашёл, задача переходит в `uncertain` для ручной сверки. Это уменьшает риск дублей, но не гарантирует отсутствие дублей при нарушении уникальности ключа в CRM, рассинхронизации резервных копий или одновременной записи сторонних интеграций. В EspoCRM необходимо отдельно проверить ограничения уникальности и резервирование. Этот адаптер создаёт отдельный контакт на каждую карточку `case_id`; объединение контактов между разными карточками не реализовано.

Другие CRM подключаются собственной реализацией `CRMProvider` и адаптацией очереди. Реализации amoCRM и Битрикс24 ещё нет; стоимость и наличие API зависят от их тарифов.

## Telegram

`TELEGRAM_ENABLED=false` по умолчанию. После создания собственного бота и чата задайте `TELEGRAM_ENABLED=true`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в локальном `.env`, не публикуйте их и не отправляйте в чат. Для проверки бот должен иметь право писать в выбранный чат. Реальная отправка ещё не проверена. Ошибки `429` повторяются после указанного API срока и с ограничением числа попыток. При сетевой ошибке после отправки результат может быть неизвестен; задание переводится в `uncertain` для сверки, а не отправляется повторно автоматически.

## Напоминания и отчёт

Только для тестового провайдера: статус `demo_crm.status = 'new'` означает необработанную заявку. Через `FOLLOWUP_MINUTES` создаётся одно напоминание в Telegram; перед отправкой статус проверяется снова. Смена статуса в таблице требует отдельного интерфейса или SQL с ограниченным доступом. Для EspoCRM предусмотрено периодическое чтение стадии сделки: напоминание создаётся только при свежем статусе, совпадающем с `ESPO_UNPROCESSED_STAGE` (по умолчанию `Prospecting`), и статус повторно проверяется перед отправкой. Это работает только после настройки и проверки реальной CRM; название стадии следует уточнить в конкретной воронке. Ошибка чтения не считается подтверждением просрочки.

`demo_analytics` показывает только агрегаты: количество событий, карточек, новых записей и ошибочных или неопределённых доставок. Это техническая демонстрация, не аналитика продаж.

## Локальная конфигурация и ограничения

Скопируйте `.env.example` в `.env`, задайте локальные секреты и запустите `docker compose up -d --build`. Обновление существующей базы: перед применением `002_integrations.sql` создайте проверенную резервную копию; сначала протестируйте миграцию на отдельной базе. Папка initdb в Compose применяется только к пустому тому. Пример не настраивает автоматические миграции, привилегии и TLS; его нельзя публиковать в интернете.

При ошибках `failed` и `uncertain` требуется ручная проверка, журнал не содержит тела ответа или персональных данных. Интерфейс управления этими заданиями, полноценный журнал аудита, проверка реальных сервисов, контрольный тест восстановления и развёртывание EspoCRM — следующие задачи. Реальная CRM и Telegram не включаются автоматически.
