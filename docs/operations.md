# Эксплуатация локального демо

Эта памятка относится к уже настроенному локальному стенду из [руководства](../infra/local-demo/README.md), а не к серверу. Имена контейнеров ниже — примеры для проектов `remont-trial`, `remont-local-automation` и `remont-local-crm`. Если они отличаются, сначала определите фактические имена. Не останавливайте и не перенастраивайте другие контейнеры.

## Проверить состояние

```sh
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
curl http://127.0.0.1:18080/health
docker exec remont-trial-receiver-1 python -m app.diagnostics
```

`/health` подтверждает только ответ процесса. Диагностика показывает агрегированные состояния очередей без содержимого заявок: `pending` может быть нормальным ожиданием, а `overdue`, `expired_lease`, `failed` и `uncertain` требуют внимания. Код `1` означает обнаруженную проблему очереди, `2` — невозможность выполнить диагностику. Детальное описание и необязательный монитор — в [диагностике](queue-diagnostics.md).

Команда отчёта за неделю, также без имён и телефонов:

```sh
docker exec remont-trial-receiver-1 python -m app.analytics --days 7
```

Это количество и состояния принятых заявок, а не подтверждённые продажи. Подробнее — [аналитика](analytics.md).

## Если заявка не дошла

1. Проверьте, включён ли компьютер и Docker и доступна ли опубликованная форма. Если изменился адрес временного туннеля, ранее настроенный webhook может указывать на старый адрес; обновление настройки в Tilda и отдельная проверка описаны в [инструкции формы](tilda/assembly.md).
2. Проверьте состояние приёмника и агрегаты очереди командами выше. Ответ `/health` не проверяет запись в БД, n8n и внешние интеграции.
3. Если событие ожидает обработки, проверьте отдельный n8n, его расписание и соединение с PostgreSQL. Тестовая копия workflow из репозитория не содержит credentials и по умолчанию не активна.
4. Если внутренняя обработка завершена, но нет сделки или сообщения, проверьте состояние задания соответствующей интеграции, конфигурацию и доступность CRM/Telegram. Детали полей и лимитов указаны в [интеграциях](integrations.md).
5. Для `uncertain` сначала вручную проверьте соответствующую сделку или чат: операция могла выполниться. Не повторяйте задание вслепую и не отмечайте его доставленным без доказательств. Процедура подтверждения Telegram — в [инструкции интеграций](integrations.md#ручная-сверка-неопределённой-доставки-telegram).

Для тестов формы используйте только вымышленные данные. Не отправляйте в переписку секреты, журналы с персональными данными и полные настройки Compose: они могут содержать действующие ключи.

## Перед обновлением или восстановлением

Проверьте состояние очереди и снимите отдельные копии PostgreSQL, данных и файлов EspoCRM, SQLite и ключа шифрования n8n, а также необходимых настроек. Снимки создаются в разное время, ключи и конфигурация требуют отдельной защиты. Копия только на том же компьютере не защищает от его потери; права файла не заменяют шифрование.

Восстанавливайте сначала в отдельное окружение и проверяйте его, не перезаписывая существующие тома. Инструменты и ограничения проверенной тренировки — в [руководстве бэкапа](../infra/backup/README.md). Автоматическая непрерывная доступность, внешнее мониторирование и полное восстановление с реальными внешними сервисами не доказаны.
