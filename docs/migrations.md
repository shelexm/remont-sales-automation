# Миграции PostgreSQL

Alembic хранит текущую ревизию в `alembic_version`. Для пустой базы контейнер `migrate` выполняет последовательно `20261105_0001` и `20261105_0002` до старта приложения. SQL в `migrations/sql` — часть конкретных ревизий: это неизменяемая начальная схема с функциями и триггером, а не скрипты Docker initdb. Новые изменения оформляются новыми ревизиями; существующие не редактируются после применения.

В локальном Compose применить новые ревизии: `docker compose run --rm migrate`. Успешное повторное применение не меняет данные. Автоматический downgrade не реализован: при ошибке нужно восстанавливать проверенный бэкап, а не удалять таблицы.

## База без Alembic

Если в схеме найдены таблицы предыдущей версии и нет записи Alembic, начальная миграция **останавливается без изменения таблиц**. Не выполняйте `stamp` вслепую: он лишь записывает номер и не проверяет структуру.

Перед переносом реальной базы создайте и проверьте резервную копию, восстановите её в отдельный стенд и сравните таблицы, индексы, функции и триггеры с конкретной версией прежней схемы. Автоматический инструмент безопасного определения версии старой базы здесь ещё не реализован. План baseline для конкретной базы и сам перенос требуют отдельной проверки; не используйте его как подтверждённый production-upgrade.

Модели SQLAlchemy описывают таблицы приложения. Интеграционный тест сравнивает их колонки, nullable, первичные и внешние ключи с результатом миграций на отдельной PostgreSQL. Функции, триггер, представление, а также все детали индексов и ограничений этим сравнением не проверяются. `alembic revision --autogenerate` пока не настроена и не заменяет ручную проверку схемы и миграций.
