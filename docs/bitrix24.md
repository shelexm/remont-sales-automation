# Экспериментальный адаптер Bitrix24

В `app/integrations/bitrix.py` подготовлен экспериментальный адаптер Bitrix24 REST API; его можно выбрать для **отдельной новой базы** через `CRM_PROVIDER=bitrix24`. Реальный портал в зоне bitrix24.ru осмотрен 11 ноября 2026 года: при попытке открыть создание входящего вебхука интерфейс потребовал отдельную подписку BitrixGPT + Маркетплейс и предложил 15-дневный пробный период. Пробный период не включался, вебхук не создан и интеграция с реальным порталом не проверена. Текущий стенд продолжает использовать EspoCRM; тесты адаптера применяют имитацию API.

## Что реализовано в адаптере

- Проверка HTTPS-адреса входящего вебхука и метаданных двух настраиваемых строковых полей контакта и сделки перед записью.
- Поиск по отдельному техническому ключу установки и карточки; проверка идентификатора и значения поля в ответе. При нескольких совпадениях, неполном списке или неверном фильтре обработка останавливается с `uncertain`.
- Повторное использование единственного видимого контакта с совпадающим нормализованным телефоном. При нескольких совпадениях выбор не делается. Другие форматы номера, скрытые правами контакты и одновременное создание другой интеграцией могут привести к пропуску дубля; глобальная уникальность не гарантируется.
- Создание контакта и сделки с RUB и записью намерения в журнал до запроса. После создания адаптер перечитывает объект и проверяет технический ключ. Неизвестный результат записи не приводит к повторному созданию вслепую; при подтверждённом ограничении запросов предусмотрена задержка. У существующей сделки обновляется бюджет и привязка контакта.
- Чтение стадии сделки по ID и проверка свежего статуса перед напоминанием. Для Telegram необходимо явно задать код начальной стадии конкретной воронки в `BITRIX_UNPROCESSED_STAGE`; проверено только с имитацией CRM.

Входящий webhook содержит секрет прямо в URL. Не размещайте его в Git, документации, логах или чате; ротацию и права выполняйте в самом Bitrix24. Два технических поля должны быть доступны на чтение и запись, не быть множественными и использоваться только этим решением. Для каждой независимой установки требуется собственный постоянный `installation_id`; повторное использование идентификатора с общей CRM способно смешать записи. Все методы поиска видят только данные, доступные пользователю вебхука.

## Доступность на текущем тарифе

По [справке Bitrix24](https://helpdesk.bitrix24.ru/open/20886106/) для создания вебхуков и приложений требуется подписка BitrixGPT + Маркетплейс. Это условие относится к порталу Bitrix24, а не к домену сайта, с которого поступает заявка. Срок пробного доступа и дальнейшие условия следует проверять в конкретном аккаунте. Для полностью бесплатной работающей интеграции в текущем демо используется локальная EspoCRM.

## Что нужно до реального включения

Нужен тестовый портал Bitrix24 с доступным REST API, пользователь и входящий webhook с минимальными правами на контакты и сделки, два пользовательских поля, отдельная база и проверка на вымышленных данных. Надо проверить реальные форматы полей, поиск, задержку индексации, ошибки и лимиты конкретного тарифа, права, валюту и стадии. Стадию для напоминаний выбирают по настройке конкретной воронки.

После создания новой отдельной базы задайте в защищённом локальном env `BITRIX_WEBHOOK_URL`, `BITRIX_CONTACT_FIELD`, `BITRIX_DEAL_FIELD`, постоянный уникальный `BITRIX_INSTALLATION_ID` и при использовании Telegram `BITRIX_UNPROCESSED_STAGE`. Файл `infra/local-demo/bitrix-override.yaml` передаёт настройки обработчику; используйте его вместо EspoCRM override и не запускайте предварительно demo-обработчик на этой базе. Заглушки `env.example` не являются рабочими данными. Не выводите `docker compose config` с настоящим вебхуком.

Новый обработчик записывает привязку провайдера и портала в своей базе и при следующем запуске отказывает при несовпадении. База со старой историей CRM без такой привязки не может быть принята Bitrix24, даже с флагом ручного принятия старой конфигурации. Это защита от случайного переключения, а не миграция: для другой CRM используйте отдельную базу и процесс переноса с проверкой. Перед включением остановите все старые версии обработчика: они не знают о привязке и не обеспечивают такую защиту. Если работает несколько разных версий одновременно или администратор вручную изменит базу, эта защита не гарантируется.

Справка Bitrix24: [список контактов](https://apidocs.bitrix24.com/api-reference/crm/contacts/crm-contact-list.html), [создание контакта](https://apidocs.bitrix24.com/api-reference/crm/contacts/crm-contact-add.html), [список сделок](https://apidocs.bitrix24.com/api-reference/crm/deals/crm-deal-list.html), [создание сделки](https://apidocs.bitrix24.com/api-reference/crm/deals/crm-deal-add.html), [ограничения REST API](https://apidocs.bitrix24.com/settings/performance/limits.html). Актуальные условия доступа к API нужно отдельно проверять для выбранного аккаунта и тарифа.
