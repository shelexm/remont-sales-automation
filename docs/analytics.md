# Сводный отчёт по заявкам

После обновления локального контейнера приёмника отчёт за последние 30 дней запускается так:

```sh
docker exec remont-trial-receiver-1 python -m app.analytics
docker exec remont-trial-receiver-1 python -m app.analytics --days 7
docker exec remont-trial-receiver-1 python -m app.analytics --days 30 --json
```

Период — от текущего момента минус указанное число суток до текущего момента, UTC, левая граница включается; допустимо 1–365 дней. Все запросы выполняются в одной транзакции PostgreSQL только для чтения с общим согласованным снимком. Команда не выводит имена, телефоны, бюджеты, идентификаторы заявок или токены. Из payload выводятся только заранее разрешённые категории услуг и классы бюджета; неизвестные значения учитываются как `unknown`.

## Как читать показатели

- **Принято уникальных событий** — сохранённые события с разными идентификаторами источника. Повторная доставка того же webhook обычно не создаёт событие и отдельно не подсчитывается. Ошибочные и отклонённые до записи формы тоже сюда не входят.
- **Обработано / ожидает / в обработке / ошибка** — текущий статус событий, принятых в выбранный период, а не число действий, совершённых за период.
- **Первое / повторное событие карточки** — связь обработанного события с первой заявкой карточки или последующей в соответствии с текущим правилом объединения по телефону и услуге. Необработанные события учитываются как «без карточки». Это не число уникальных людей и не все возможные дубли.
- **Услуга и класс бюджета** — классификация каждого сохранённого события, включая ещё не обработанные. Класс зафиксирован при приёме по настроенному тогда порогу и не пересчитывается при его изменении. Сумма бюджетов не считается выручкой.
- **CRM, Telegram, напоминания** — текущие статусы заданий, связанных с событиями выбранного периода. Напоминание может быть создано позже периода. `done` означает завершённое задание или вручную подтверждённую доставку, но не успешную продажу. Ранее данные могли проходить через demo CRM; по одному этому отчёту нельзя доказать создание сделки в конкретной внешней CRM.
- **Обработано без задания CRM** — события со статусом `completed`, для которых в момент отчёта нет задания CRM. При ненулевом значении нужна техническая проверка.

Показатели не являются финансовой отчётностью: статусы воронки, подтверждённые продажи, стоимость лида и конверсия здесь не рассчитываются. Локальный стенд содержит синтетические заявки; их нельзя представлять как клиентов или коммерческие результаты. Отчёт доступен только при работающих Docker и базе, сам не отправляется и не заменяет мониторинг.
