# Приём заявок: состояние разработки

Приёмник обрабатывает POST `/webhook/tilda` с `Content-Type: application/x-www-form-urlencoded` и заголовком `X-Webhook-Key`. Tilda позволяет задать ключ для передачи в заголовке; `test=test` получает `200` без записи. Контракт необходимо подтвердить реальной формой при её подключении.

Обязательные поля: `tranid` (идентификатор Tilda), `Name`, `Phone`, `Service` (`cosmetic`, `capital`, `design`, `other`), `Area` (1–10000 целых м²), `Budget` (1–1000000000 целых рублей), `Consent` (`yes`, `1`, `true` или `on`). Телефоны поддерживаются только российские; значения без кода страны трактуются как российские. Классификация идёт по `HIGH_BUDGET_THRESHOLD` (демо-порог, по умолчанию 1 млн ₽). Порог и справочник услуг должны быть согласованы с владельцем до публикации.

Событие сохраняется в PostgreSQL до ответа `200`; повтор с тем же `tranid` и теми же нормализованными данными не создаёт новую запись. Другие данные с тем же `tranid` возвращают `409`. Ошибка базы — `503`, ошибки данных — `422`, неверный ключ — `401`. Технический лог приложения не содержит поля заявки. Данные хранятся в БД в открытом виде: защиту доступа, срок хранения, резервное копирование и удаление необходимо настроить до работы с реальными данными.

В базе есть атомарный захват с блокировкой строк, ограниченным числом попыток, временем аренды и токеном для отклонения запоздавших подтверждений. **Потребитель очереди и подключение n8n ещё не реализованы:** события останутся в состоянии `pending`; ничего не отправляется в CRM или Telegram. Это не демонстрация полного процесса и не готовая к публичному запуску система. Сопоставление повторных обращений одного клиента с разными `tranid`, политика CRM и мониторинг также впереди.

## Локальный запуск

Скопируйте `.env.example` в `.env`, замените оба секрета длинными случайными буквенно-цифровыми значениями и выполните `docker compose up -d --build`. Сервис слушает только `127.0.0.1:18080`, существующий n8n не изменяется. `GET /health` проверяет только процесс, а не готовность PostgreSQL. Первоначальная схема загружается при создании пустого volume; миграция уже существующих volume пока не реализована. Для текущего этапа используйте только тестовые данные.

Отдельный тестовый PostgreSQL можно передать через `TEST_DATABASE_URL` при запуске `python3 -m unittest discover -s tests -v`. Интеграционные тесты очищают таблицу `lead_events` в указанной базе: указывайте **только отдельную одноразовую тестовую базу**. Без этой переменной тесты БД пропускаются. CI поднимает отдельный сервис PostgreSQL.
